// bring your own machine

Three ways
into the flock.

Each machine names a provider. Capabilities are explicit, and an unsupported operation fails cleanly.

ssh

Anything you can SSH into: a cloud VM, a guest, or a box under the desk.

[machines.devbox]
provider = "ssh"
host = "devbox.example.com"
user = "ubuntu"
workdir = "~/src/myrepo"
ports = { app = 3000 }

command

Lima, Multipass, OrbStack, Tart, or another VM tool with a CLI. Give each operation a shell template.

[machines.lima]
provider = "command"
instance = "default"
status = "limactl list {instance} --json"
shell = "limactl shell {instance}"
up = "limactl start {instance}"

gcp-worker

Bundle's disposable GCP workers, with agent.py retaining authority over leases, caps, source, and deletion.

[providers.gcp-worker]
kit = "~/Work/bundle/scripts/gcp-worker"
repo = "~/Work/bundle"

[machines.heavy]
provider = "gcp-worker"
task = "heavy"
create = { lease = "1h", ttl = "4h" }

// safe by default

See the move
before it happens.

Lifecycle commands print their plan first. Add --yes only when it looks right.

cloudsheep down heavyplan
machine: heavy
action: down
applied: False
effect: collects into a new branch, then DELETES the VM
would_run:
  python3 agent.py release ...

nothing done; rerun with --yes to apply
01

Plan, then apply

up, down, and extend show the action without applying it. --yes is the deliberate step.

02

Collect, don't overwrite

Changes come back on a new local branch. Your HEAD, index, and working tree stay untouched.

03

Skip secret-looking paths

SSH sync reports and skips .env*, keys, .ssh/, .aws/, and related paths (while allowing example, sample, and template env files). It is a useful guardrail, not a secret scanner.

04

Disconnect freely

On SSH machines, detached jobs live under ~/.cloudsheep/jobs and survive your connection. Follow logs later, or cancel the process group.

// install

Two commands.
Then add a machine.

  1. Put the CLI on your path.Cloudsheep is Python standard library only.
  2. Write the starter config.cloudsheep init copies the example to ~/.config/cloudsheep/machines.toml.
  3. Uncomment what you use.Plain SSH, a command-line VM tool, or bundle's GCP workers.

Needs Python 3.11+. The SSH provider uses ssh and rsync; the herdr picker uses fzf and jq.

~/Work/cloudsheep
$ ln -s ~/Work/cloudsheep/bin/cloudsheep \
  ~/.local/bin/cloudsheep
$ cloudsheep init
wrote ~/.config/cloudsheep/machines.toml; edit it to add your machines

$ $EDITOR ~/.config/cloudsheep/machines.toml
$ cloudsheep ls

devbox  ssh         ubuntu@devbox.example.com
lima    command     default

$ cloudsheep shell devbox
ubuntu@devbox:~/src/myrepo$ _
